Adding a New Model

How to Add a New AI Model

Three files. Zero plumbing. The game UI, training page, and simulator pick it up automatically.

Start here: every agent in this project is built from up to three files, and each one has exactly one job. Skim this before opening the examples below — it's why the two starter templates don't look alike.
1. Agent class — always required

The decision-maker. One method, choose_action(game), that looks at the current board and returns a move. Every agent needs this file and nothing else is mandatory.

→
2. Registry entry — always required

One dict added to registry.py — your agent's business card: a name, where to import it from, whether it's trainable. The Play, Train, Simulate, and Leaderboard pages all read this list; you never touch those pages directly.

→
3. Training script — only if trainable

A separate program that plays the agent against itself thousands of times and saves improved weights to disk. Skip it entirely if your agent has nothing to learn — e.g. it's pure search over hand-picked numbers.

That's the whole reason basic_minimax.py and cnn_basic.py look so different below: one ships files 1 and 2, the other ships all three. They sit at opposite ends of the same spectrum — a human wrote the "knowledge" for one; a training loop grinds it out for the other. Same interface, same registry shape, wildly different insides.

Download a Working Example

Two starter templates ship with the project — pick the one that matches the kind of agent you want to build. Both are minimal, already registered, and runnable end-to-end.

Or generate the files instead of downloading and renaming them by hand:

# non-trainable, classical-search shape
python scripts/new_agent.py my_agent --template minimax

# trainable shape (also stubs a training script)
python scripts/new_agent.py my_agent --template cnn

Both write the agent class file, register it in Agents/registry.py, and (for cnn) stub a training script — fill in the TODOs it leaves behind.

Basic Minimax

Classical · Search-based

Depth-limited alpha-beta with a hand-crafted linear evaluator (harmony count, material, ring distance, opponent threat). No neural net, no gradients — just search + a few hardcoded weights.

Inside the file

  • evaluate() — the hand-tuned scoring formula: counts harmonies, ring distance, material, opponent threats
  • _alphabeta() — the tree search that plays moves ahead and keeps the best-scoring line
  • No training script — the numbers in evaluate() are the whole "model"; there's nothing to learn
basic_minimax.py — agent class registry.py — registration

Basic CNN

Learned · Value network

Tiny two-layer convolutional value network over an 8-channel 19×19 board tensor. Greedy 1-ply lookahead picks the move leading to the highest-valued successor state. Trained by self-play value-regression.

Inside the files

  • encode_board() — turns the board dict into an 8-channel tensor the network can actually read
  • BasicCNN — the network itself: two conv layers + a linear "how good is this position" head
  • cnn_basic_training.py — plays the net against itself, nudges its guesses toward who actually won, saves the weights
cnn_basic.py — agent class cnn_basic_training.py — training script registry.py — registration

Which one should I copy?

If your agent's intelligence is a formula or search you can write down directly — rules, heuristics, MCTS — start from Basic Minimax; you'll only ever touch files 1 and 2. If it should get better by playing itself over and over — a neural net, a Q-table, anything reward- or gradient-trained — start from Basic CNN; cnn_basic_training.py is the template for file 3. Both register the exact same way, so the registry.py download is identical either way.

Swap the evaluator, widen the feature vector, change the net architecture, or replace the training loop — every extension point is isolated to one of these files.

1 Create the Agent Class

Create a new file in Agents/rl/ (or Agents/classical/). Your agent class must implement one method:

# Agents/rl/my_agent.py

class MyAgent:
    def __init__(self, player=1, load=False, **kwargs):
        # Initialize your model / load weights when load=True
        ...

    def choose_action(self, game, verbose=False):
        """Return one legal action: ('plant', flower, r, c) or ('arrange', fr, fc, tr, tc)."""
        legal = game.get_legal_actions()
        # ... your logic ...
        return best_action

Interface requirements

  • choose_action(game, verbose=False) — takes a PaiShoGame instance, returns an action tuple.
  • Constructor should accept load=True to restore pre-trained weights at play time.
  • If your model needs to know which player it is, accept player= in __init__. The system will set agent.player before each move if you set "needs_player": True in the registry.

Optional methods for training

  • save_model(path=None) — persist weights to disk.
  • load_model(path=None) — restore weights from disk.
Tip: Use game.clone() before simulating moves in search. Never mutate the original game object.

2 Create a Training Script (optional)

If your model is trainable, add a script at Agents/training/my_agent_training.py. It should:

  • Accept hyperparameters as CLI arguments (e.g. --n, --lr, --eps).
  • Print progress to stdout so the training dashboard can parse it.
  • Save the trained model to data/params/MyAgent/.

Stdout format for live progress

The training dashboard parses stdout lines to show real-time stats. You can reuse an existing log format or add a new parser. The built-in parsers recognize these formats:

# PPO / Set Transformer format (log_parser: "ppo")
Episode 100/5,000 | eps=0.28 | P1 wins in 234 steps | W1=55 W2=40 D=5 | PL=0.023 VL=0.156 | params=12,544 | 3.21s

# TD Learning format (log_parser: "td_learning")
Episode 100/5,000 | eps=0.28 | P1 wins in 234 steps | W1=55 W2=40 D=5 | 3.21s

# Monte Carlo format (log_parser: "monte_carlo")
Episode 100/1,000 | Eps: 0.95 | P1 wins in 312 steps | Q-Table: 45,231 (+128) | Took 1.23s

# NEAT format (log_parser: "neat")
Generation 25
Tip: The easiest path is to print in the PPO format and set "log_parser": "ppo" in the registry. If you need a custom format, add a regex + extractor function to ui/training_manager.py's _LOG_PARSERS dict.

3 Register in Agents/registry.py

Add one dictionary entry to the AGENTS list. Here's a minimal example for a trainable agent:

{
    "key": "my_agent",                   # unique identifier
    "display_name": "My Agent",          # shown in UI
    "description": "Short description",  # shown on model card
    "kind": "class",
    "module": "Agents.rl.my_agent",          # Python import path
    "class_name": "MyAgent",             # class to instantiate
    "play_kwargs": {"player": 1, "load": True},  # constructor args for play
    "needs_player": True,                # set agent.player each turn
    "play_params": [],                   # runtime-tunable params (game UI)
    "model_path": "data/params/MyAgent/model.pt",   # where weights live
    "training_script": "Agents/training/my_agent_training.py",
    "training_params": [                 # shown on training page; use the num_param/
                                          # text_param/checkbox_param helpers instead of
                                          # raw dicts — see existing entries for examples
        num_param("episodes", "Episodes", 5000, step=500, min=1,
                  tooltip="Number of self-play episodes", cli_flag="--n"),
        num_param("lr", "Learning Rate", 0.001, step=0.0001,
                  min=0.00001, max=0.1, cli_flag="--lr"),
        checkbox_param("resume", "Resume", False,
                       tooltip="Continue from saved checkpoint", cli_flag="--resume"),
    ],
    "total_episodes_key": "episodes",    # drives the progress bar
    "log_parser": "ppo",                 # reuse PPO's stdout parser
    "config_file": null,                 # editable config file path, or null
}

Registry field reference

FieldDescription
keyUnique machine name, used in URLs and CLI specs.
display_nameHuman-readable name shown in both UIs.
descriptionOne-line description for model cards.
kind"class" for agents, "function" for standalone functions, "inline" for random.
modulePython import path (e.g. Agents.rl.my_agent). Lazy-imported on first use.
class_nameClass to instantiate from the module.
play_kwargsDict passed to the constructor when loading for play.
needs_playerIf true, the system sets agent.player = current_player before each move.
play_paramsRuntime-tunable parameters shown in the game UI (e.g. time budget), built with num_param/text_param/checkbox_param from registry.py.
model_pathRelative path to saved weights. Used by the training dashboard to show file info. null if none.
training_scriptRelative path to the training script. null if not trainable (agent won't appear on training page).
training_paramsHyperparameter definitions for the training UI, built with the same num_param/text_param/checkbox_param helpers. Each carries key, label, type, default, an optional tooltip/min/max/step, and a required cli_flag — the CLI flag on the training script this param maps to (e.g. cli_flag="--n"). No separate CLI-mapping table to keep in sync.
total_episodes_keyWhich training_params key represents the total count (drives the progress bar).
log_parserKey into the parser registry in training_manager.py. Reuse "ppo", "td_learning", "monte_carlo", "neat", or add your own.
config_filePath to an editable config file (shown in training UI). null for most agents.
Tip: Run python -m Agents.registry (or python tests/test.py) after editing the registry — validate_registry() checks every entry's module/class_name/function_name actually resolve and that every trainable param has a cli_flag, so typos fail immediately instead of 500ing the first time someone picks your agent in the UI.

That's It

Once those three pieces are in place:

  • Your agent appears in the game page player dropdowns automatically.
  • If trainable, it appears on the training page with its own model card and hyperparameter form.
  • The simulator (python backend/simulator.py --p1 my_agent) can load it with no changes.

Testing your agent

# Quick check: run a local game
python backend/simulator.py --mode local --p1 my_agent --p2 random --n 1

# Train from the UI
python backend/ui/server.py
# Open http://localhost:5000/train and select your model

# Run the test suite
